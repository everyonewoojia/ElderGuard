## 1 引言

### 1.1 文档目的

本架构设计文档基于修订后的需求文档以及小组内部统一约定开展设计，确定 “银发守护” 空巢老人智能看护系统的整体架构、技术栈、模块划分、设计模式、质量场景，明确 P0/P1/P2 实现边界，指导原型开发，满足软件体系结构实验要求。系统包含老人端 AI Agent、家属微信小程序、Agent 中枢服务三大部分，实现感知-理解-规划-执行-反馈-记忆完整闭环。

### 1.2 范围

架构覆盖边缘老人端、云端服务、AI 能力层、数据存储层、外部接入层。严格区分 P0 必须实现、P1 尽量实现（允许模拟）、P2 仅预留接口，不包含底层硬件驱动开发，硬件仅做接口适配。

### 1.3 与需求文档对应关系

架构完全对齐需求文档四大业务模块：日常主动陪伴、居家安全监护、家属远程联动、多模态指令交互，落实可靠性、安全性、可用性、可修改性、性能、易用性六大质量属性，严格遵循业务、技术、法律伦理约束。

## 2 架构样式（架构风格）

> 统一表述：本系统采用 “分层架构为主，结合微内核架构、事件驱动架构、Agent 代理架构” 的混合架构样式，并参考边缘-云协同参考架构。

**分层架构**，划分五层：接入层、应用服务层、Agent 智能业务层、AI 能力支撑层、数据持久层。每层职责独立，层间单向调用，降低耦合。接入层接收两端请求；应用服务层处理通用业务；Agent 智能业务层实现陪护 Agent 核心；AI 能力支撑层封装各类 AI 接口；数据持久层完成全部数据持久化。

**微内核架构**：内核仅保留事件总线、任务规划调度、记忆管理；陪伴、提醒、告警、指令解析等业务逻辑以插件形式实现。新增看护技能不改动内核源码，实现可扩展。

**事件驱动架构**：系统所有状态变化封装为标准事件对象，例如跌倒事件、久坐事件、语音指令事件、家属配置变更事件。事件总线完成事件发布与订阅，告警、提醒业务通过事件流转解耦。高危事件设置高优先级，优先被调度处理。

**Agent 代理架构**，严格执行感知-理解-规划-执行-反馈-记忆闭环。感知模块接收多模态输入；理解模块做意图、场景解析；规划模块完成任务编排、风险分级；执行模块调用插件；反馈模块输出语音与界面结果；记忆模块更新用户档案。

## 3 参考模型与参考架构

### 3.1 参考模型

本项目参考模型以智能 Agent 闭环模型为核心，结合分层职责划分。智能 Agent 闭环模型将系统抽象为感知、理解、规划、执行、反馈、记忆六个环节，形成持续运行的服务闭环。具体到“银发守护”系统，各环节职责如下：

- **感知**：接收老人语音、按键操作、本地计时事件、家属配置、隐私授权状态，以及可选的视觉输入。
- **理解**：对语音、文本、事件进行意图解析、场景判断、风险分级，识别老人当前需求与安全状态。
- **规划**：根据理解结果和记忆信息，编排任务，确定优先级，选择对应的业务技能插件。
- **执行**：调用提醒、告警、求助、查询、陪伴等业务插件，执行具体动作。
- **反馈**：通过语音、界面文字、消息推送等方式，向老人、家属或社区工作人员反馈结果。
- **记忆**：维护短期会话记忆和长期用户档案，包括老人偏好、交互历史、监护日志、提醒任务、告警记录等。

同时，系统采用分层参考模型，将职责划分为接入层、应用服务层、Agent 智能业务层、AI 能力支撑层、数据持久层。下层为上层提供服务，上层不得反向侵入下层。各层职责独立，层间单向调用，以降低耦合。

参考模型不涉及具体实现，只定义系统必须包含的功能角色及其协作关系。后续架构设计、模块划分、接口设计均以此为基础。

### 3.2 参考架构

在参考模型基础上，本项目采用边缘-云协同参考架构。系统分为边缘端、云端、家属端三个部署部分，各部分职责与边界如下。

**边缘端**

部署在老人原型终端，运行老人端 Agent。负责本地感知采集、本地计时提醒、事件预处理、本地缓存和离线降级。原始音视频默认保存在边缘本地，仅在用户显式授权后才上传云端。边缘端在断网时仍能执行 P0 核心业务，如用药作息提醒、主动语音求助、久坐计时提醒、本地语音告警；网络恢复后同步数据。离线降级能力属于 P1 需求。

**云端**

部署 Agent 中枢服务，运行接入层、应用服务层、Agent 智能业务层、AI 能力支撑层、数据持久层。负责集中持久化记忆、家属业务处理、告警分发、指令同步、AI 能力调用和数据存储。云端不直接访问老人边缘设备，而是通过安全接口接收边缘上报事件、下发配置任务。

**家属端**

微信小程序，运行于家属手机。通过公网 REST / WebSocket 访问云端中枢，不直接与老人边缘设备通信。家属端只负责查看老人状态、告警记录、配置提醒任务、调整通知策略等，所有请求经云端鉴权与权限隔离。

边缘端与云端之间通过安全通道通信，传输事件、告警、任务同步、授权状态等。家属端与云端之间通过 REST 和 WebSocket 通信。三个部分之间边界清晰，实现安全隔离、离线可用、隐私保护。

### 3.3 参考模型到参考架构的映射

为便于后续模块划分和接口设计，将参考模型中的功能角色映射到参考架构的部署部分，如下表所示。

| 参考模型角色 | 边缘端 | 云端 | 家属端 |
| --- | --- | --- | --- |
| 感知 | 语音、按键、计时、可选视觉、本地环境 | 接收边缘上报事件、家属配置 | 接收家属输入 |
| 理解 | 本地基础意图、本地事件预处理 | 云端意图理解、多模态融合 | 无 |
| 规划 | 本地任务调度、告警优先级 | 云端任务编排、告警分发 | 无 |
| 执行 | 本地提醒、本地语音告警、插件执行 | 推送告警、同步任务、调用 AI | 展示信息、配置任务 |
| 反馈 | 本地语音、界面文字 | 消息推送、接口响应 | 界面展示、通知 |
| 记忆 | 本地缓存、短期记忆、离线日志 | 长期记忆、用户档案、监护日志、告警记录 | 无持久化 |

该映射表明：边缘端侧重实时性、离线可用和隐私保护；云端侧重持久化、全局调度和家属协同；家属端侧重交互与配置。后续模块划分、接口设计、质量场景设计均以此映射为依据。

## 4 系统模块划分与功能说明

系统采用分层结构，自上而下分为接入层、应用服务层、Agent 智能业务层、AI 能力支撑层、数据持久层。各层职责独立，层间单向调用。模块编号规则：M-层名缩写-序号。

### 4.1 接入层

接入层负责接收老人端、家属端及外部系统的请求，完成协议转换、初步校验和请求转发。

| 模块编号 | 模块名称 | 职责 | 优先级 | 依赖 | 对外接口 |
| --- | --- | --- | --- | --- | --- |
| M-ACC-01 | 老人端接入模块 | 接收老人语音、按键、本地计时事件，转发至边缘 Agent | P0 | 麦克风、老人端界面 | 本地事件接口 |
| M-ACC-02 | 家属小程序接入模块 | 处理家属小程序 REST 请求，完成登录、查询、配置等 | P0 | 微信小程序、云端鉴权 | REST |
| M-ACC-03 | WebSocket 实时消息模块 | 向家属小程序实时推送告警事件 | P1 | WebSocket、消息队列 | WebSocket |
| M-ACC-04 | 第三方硬件适配模块 | 预留毫米波雷达、穿戴设备等抽象适配接口 | P2 | 无（仅接口） | 适配器接口 |

接入层不直接访问数据库，所有请求经应用服务层处理。老人端与家属端请求严格隔离，家属端不得直接访问老人边缘设备。

### 4.2 应用服务层

应用服务层处理通用业务逻辑，包括鉴权、告警通知、任务同步、日志记录、告警重试等。

| 模块编号 | 模块名称 | 职责 | 优先级 | 依赖 | 对外接口 |
| --- | --- | --- | --- | --- | --- |
| M-APP-01 | 用户权限管理模块 | 家属登录鉴权、账号数据隔离、角色权限校验 | P0 | 数据库、鉴权服务 | REST |
| M-APP-02 | 基础告警通知模块 | 高危告警推送至家属小程序 | P0 | 消息推送通道、WebSocket | REST / WebSocket |
| M-APP-03 | 任务同步模块 | 将家属配置的提醒任务下发至老人边缘端 | P0 | 数据库、边缘通信接口 | REST |
| M-APP-04 | 监护日志模块 | 记录全部事件、告警、提醒、交互日志 | P0 | 数据库 | REST |
| M-APP-05 | 告警重试模块 | 网络异常或推送失败时重发告警 | P1 | 本地缓存、重试队列 | 内部接口 |
| M-APP-06 | 社区后台对接模块 | 预留社区养老后台告警对接接口 | P2 | 无（仅接口） | REST |

应用服务层是云端业务处理的核心，负责将接入层请求转化为对 Agent 智能业务层或数据持久层的调用。

### 4.3 Agent 智能业务层（微内核）

Agent 智能业务层采用微内核结构。内核仅保留事件总线、任务规划调度器、记忆管理单元；业务技能以插件形式实现，支持动态注册与隔离。

| 模块编号 | 模块名称 | 职责 | 优先级 | 依赖 | 接口 |
| --- | --- | --- | --- | --- | --- |
| M-AGT-01 | 事件总线 | 事件发布订阅、优先级分发、插件解耦 | P0 | 无 | publish / subscribe |
| M-AGT-02 | 任务规划调度器 | 风险分级、任务编排、高优先级告警优先调度 | P0 | 事件总线、记忆管理 | schedule |
| M-AGT-03 | 记忆管理单元 | 维护短期会话记忆与长期用户档案 | P0 | 数据持久层 | memory |
| M-AGT-04 | 提醒插件 | 用药、作息、久坐提醒 | P0 | 事件总线、记忆管理 | init / start / stop / handleEvent |
| M-AGT-05 | 安全告警插件 | 跌倒、求助、异常事件告警 | P0 | 事件总线、告警通知 | init / start / stop / handleEvent |
| M-AGT-06 | 指令解析插件 | 解析老人语音、按键指令，匹配技能 | P0 | 事件总线、AI 门面 | init / start / stop / handleEvent |
| M-AGT-07 | 主动陪伴插件 | 主动问候、情感陪伴闲聊 | P1 | 事件总线、AI 门面 | init / start / stop / handleEvent |
| M-AGT-08 | 高级情绪识别插件 | 预留高级情绪识别接口 | P2 | 无（仅接口） | init / start / stop / handleEvent |

微内核结构使新增看护技能无需修改内核代码，仅需注册新插件，满足可修改性要求。

### 4.4 AI 能力支撑层

AI 能力支撑层对外统一封装 AI 调用，屏蔽第三方接口差异，提供门面接口。

| 模块编号 | 模块名称 | 职责 | 优先级 | 依赖 | 接口 |
| --- | --- | --- | --- | --- | --- |
| M-AI-01 | ASR 语音识别 | 将老人语音转为文本 | P0 | 外部 ASR API | asr(audio) |
| M-AI-02 | TTS 语音合成 | 将文本转为语音播报 | P0 | 外部 TTS API | tts(text) |
| M-AI-03 | 基础意图理解 | 解析指令意图 | P0 | 外部大模型 API | intent(text) |
| M-AI-04 | 轻量行为识别接口 | 视觉跌倒、久坐识别 | P1 | 外部轻量模型/API | behavior(image) |
| M-AI-05 | 多模态融合优化 | 多模态融合优化 | P2 | 无（仅接口） | fuse(inputs) |

AI 能力支撑层不存储业务数据，仅提供能力调用。外部 API 失败时，由上层执行兜底策略。

### 4.5 数据持久层

数据持久层负责数据存储、查询、清理和扩展。

| 模块编号 | 模块名称 | 职责 | 优先级 | 依赖 | 接口 |
| --- | --- | --- | --- | --- | --- |
| M-DATA-01 | 用户档案存储 | 老人档案、家属绑定关系 | P0 | SQLite / MySQL | CRUD |
| M-DATA-02 | 提醒任务存储 | 用药、作息、久坐任务 | P0 | SQLite / MySQL | CRUD |
| M-DATA-03 | 告警日志存储 | 告警事件、处理记录 | P0 | SQLite / MySQL | CRUD |
| M-DATA-04 | 日志定期清理 | 老旧日志定期清理 | P1 | 定时任务 | 内部接口 |
| M-DATA-05 | 社区批量存储优化 | 社区批量部署存储优化 | P2 | 无（仅方案） | 内部接口 |

原型使用 SQLite，扩展可切换 MySQL。原始音视频默认保存在边缘本地，仅授权后上传云端。

## 5 使用的框架与设计模式

### 5.1 技术栈

| 类别 | 技术选型 | 说明 |
| --- | --- | --- |
| 老人端 | Python + 语音 SDK | 原型运行于安卓/鸿蒙设备 |
| 家属端 | 微信小程序原生框架 | 无需独立安装 APP |
| 云端中枢 | FastAPI（Python） | 提供 REST / WebSocket 服务 |
| 接口 | REST + WebSocket | 家属端与云端通信 |
| 事件总线 | 内存事件总线 | 原型简化实现，后续可扩展 |
| 数据库 | SQLite（原型）/ MySQL（扩展） | 轻量部署，可迁移 |
| AI 能力 | 外部 ASR、TTS、大模型 API | 不从零训练模型 |
| 行为识别 | P1 调用轻量接口 | P0 不强制依赖 |
| 部署模式 | 边缘端 + 云端 + 家属小程序 | 边缘-云协同 |

### 5.2 设计模式及应用位置

| 设计模式 | 应用位置 | 作用 |
| --- | --- | --- |
| 插件模式 | Agent 微内核业务插件 | 统一 init / start / stop / handleEvent 接口，支持动态扩展 |
| 观察者模式 | 事件总线 | 各模块订阅对应事件，实现解耦 |
| 策略模式 | 分级告警、灵敏度配置 | 不同事件等级执行不同通知逻辑 |
| 代理模式 | Agent 作为代理 | 接收老人多模态请求，屏蔽底层 AI、存储、网络细节 |
| 门面模式 | AI 能力支撑层 | 对外统一接口，屏蔽第三方差异 |
| 单例模式 | 事件总线、调度器 | 保证全局事件统一分发 |

设计模式服务于业务和质量属性，不为了使用模式而使用。

## 6 质量场景设计

本章质量场景与需求文档第 3 章保持一致，重点说明架构层面的响应策略和涉及模块。场景编号沿用需求文档：KY 可用性、AQ 安全性、KK 可靠性、XG 可修改性、XN 性能、YY 易用性。

### 6.1 可用性场景

| 场景编号 | 场景名称 | 架构响应 | 涉及模块 | 优先级 |
| --- | --- | --- | --- | --- |
| KY01 | 网络断开离线降级 | 边缘端本地持久缓存，基础提醒继续运行；网络恢复后同步数据 | M-ACC-01、M-AGT-04、M-DATA-03 | H/P1 |
| KY02 | 系统备份与恢复 | 云端数据库定期备份，故障时利用备份恢复核心服务 | M-DATA-01、M-DATA-02、M-DATA-03 | H/P1 |
| KY03 | 硬件故障可更换 | 硬件抽象接口，故障后可更换并重新接入 | M-ACC-04、M-DATA-05 | M/P1 |

### 6.2 安全性场景

| 场景编号 | 场景名称 | 架构响应 | 涉及模块 | 优先级 |
| --- | --- | --- | --- | --- |
| AQ01 | 家属账号鉴权隔离 | 接入层与应用层双重鉴权，数据库行级隔离 | M-APP-01、M-ACC-02 | H/P0 |
| AQ02 | 未授权不采集 | 所有感知模块执行前强制校验授权标记，未授权跳过并记录 | M-ACC-01、M-AGT-04、M-DATA-03 | H/P0 |
| AQ03 | 防止恶意攻击 | 防火墙、身份验证、限制访问、验证码、限流 | M-APP-01、M-ACC-02 | H/P0 |

## 8 部署架构

系统采用边缘-云协同部署，分为边缘节点、云端中枢、家属端三个部分。

**边缘节点**

运行在老人原型设备，部署老人端 Agent 程序。完成本地感知采集、计时提醒、事件本地缓存、离线降级。原始音视频默认保存在边缘本地，授权后才上传云端。边缘节点在断网时仍可执行 P0 核心业务，网络恢复后同步数据。

**云端中枢**

部署服务程序，运行接入层、应用服务层、Agent 智能业务层、AI 能力支撑层、数据持久层。接收边缘上报事件，处理家属小程序请求，完成告警分发、任务同步、数据持久化、AI 能力调用。

**家属端**

微信小程序运行于家属手机，通过公网 REST / WebSocket 访问云端中枢，不直接与老人边缘设备通信。家属端只能查看绑定老人数据，实现安全隔离。

边缘节点与云端之间通过安全通道通信，传输事件、告警、任务同步、授权状态等。家属端与云端之间通过 REST 和 WebSocket 通信。三个部分边界清晰，实现离线可用、隐私保护、安全隔离。

## 9 接口设计

### 9.1 REST 接口

| 接口 | 方法 | 说明 | 鉴权 | 优先级 |
| --- | --- | --- | --- | --- |
| /auth/login | POST | 家属登录鉴权 | 否 | P0 |
| /elder/{id}/logs | GET | 查询老人监护日志 | 是 | P0 |
| /tasks | POST/GET | 创建、查询提醒任务 | 是 | P0 |
| /alerts | GET | 查询历史告警记录 | 是 | P0 |
| /alerts/{id}/cancel | POST | 取消误告警 | 是 | P1 |
| /privacy/auth | POST | 修改隐私授权开关状态 | 是 | P0 |

所有家属接口必须携带鉴权令牌，服务端校验家属与老人的绑定关系，越权访问返回 403。

### 9.2 WebSocket 接口

/ws/alerts 用于向家属小程序实时推送告警事件。连接时需携带鉴权令牌，服务端校验绑定关系。断线后支持重连，重连后补推未确认告警。

### 9.3 统一事件 JSON 格式

```json
{
  "eventId": "string",
  "type": "fall|sedentary|voice|config|alert",
  "priority": "P0|P1|P2",
  "timestamp": "ISO8601",
  "source": "edge|cloud|family",
  "payload": {},
  "authToken": "string"
}
```

事件类型包括跌倒、久坐、语音、配置变更、告警等。priority 用于事件总线优先级调度。authToken 用于内部事件鉴权，外部请求不使用该字段。

### 9.4 插件统一接口

- `init()`：插件初始化
- `start()`：启动插件
- `stop()`：停止插件
- `handleEvent(event)`：处理输入事件

所有业务插件实现统一接口，内核通过事件总线分发事件，插件异常不影响内核和其他插件。

### 9.5 AI 门面统一接口

- `asr(audio)`：语音识别
- `tts(text)`：语音合成
- `intent(text)`：意图解析
- `behavior(image)`：行为识别（P1）
- `fuse(inputs)`：多模态融合（P2）

AI 门面屏蔽第三方 API 差异。外部 API 失败时，返回明确错误码，由上层执行兜底策略。

### 9.6 错误处理

- REST 接口返回统一错误码：400 参数错误、401 未鉴权、403 越权、404 不存在、500 服务异常。
- WebSocket 推送失败时，服务端记录并重试；家属端重连后拉取未确认告警。
- AI 接口失败时，上层使用本地固定话术、规则匹配或预置指令兜底。
- 插件异常由事件总线捕获并隔离，仅终止该插件运行。

## 10 架构约束

架构约束与需求文档第 4 章限制条件对应，编号一致。

| 编号 | 约束名称 | 架构层面落实 |
| --- | --- | --- |
| CON-B-01 | 辅助看护定位 | 架构中不设计医疗诊断模块，不输出诊疗建议 |
| CON-B-03 | 感知采集必须授权 | 所有感知模块执行前强制校验隐私授权标记 |
| CON-B-04 | 未授权采集为零 | 未授权直接跳过采集逻辑，记录授权状态变更 |
| CON-B-06 | 视觉跌倒识别仅辅助 | P0 不依赖视觉，P0 以主动语音求助为安全兜底 |
| CON-T-01 | 老人端技术栈 | Python + 语音 SDK |
| CON-T-02 | 家属端技术栈 | 微信小程序原生框架 |
| CON-T-03 | 云端技术栈 | FastAPI |
| CON-T-05 | AI 能力外部 API | 调用外部 ASR、TTS、大模型 API |
| CON-T-07 | P2 硬件仅预留接口 | 仅定义抽象适配接口，不完整编码 |
| CON-D-02 | 优先级实现策略 | P0 必须实现，P1 可模拟，P2 仅接口 |
| CON-D-07 | 核心闭环优先 | 优先保证 P0 闭环，不因扩展功能影响交付 |
| CON-L-01 | 个人信息保护 | 数据采集、存储、传输遵循最小化原则 |
| CON-L-02 | 生物与行为信息保护 | 原始音视频默认本地存储，不向无关第三方提供 |
| CON-L-03 | 禁止未许可录制传输 | 授权后才可上传，未授权不录制、不传输 |
| CON-L-05 | 数据最小化 | 只采集业务必需数据，字段、时长最小化 |
| CON-L-06 | 不提供医疗诊疗建议 | 对话、提示、告警文案不得出现诊断结论 |
| CON-E-04 | 离线缓存能力 | 边缘本地缓存 ≥ 24 小时，高危告警优先同步 |
| CON-E-05 | 网络可能中断 | 边缘端支持离线降级，网络恢复后同步 |

架构约束在开发阶段作为强制检查项，评审阶段作为验收依据。
