源码调用顺序与异常检查清单：

1. `audit_export`：`_check → _all_audit → _artifact_target → write_artifact`。
   目标先验证祖先/归属、编码字节上限及源摘要，再 `os.open(O_EXCL)`；
   打开后核对身份、设置私有权限、再次检查源，写入、flush、fsync、关闭并复读。
   已存在报 archive_exists，写入/刷盘 OSError 报 archive_write_failed；保留输出，源不提交。
2. `audit_archive`：先校验历史、操作 UUID、审核摘要、非空活动审计及索引上限。
   已有目标必须与本次操作一致，`sync_artifact` 重新刷盘并复读；新目标走上述独占流程。
   sync 失败报 archive_sync_failed；参数不一致报 operation_conflict，源变化报 revision_conflict。
3. 准备后检查累计大小及新增引用加每条告警 128 字节转换预留。
   超限报 archive_capacity / archive_marker_capacity；文件可已生成，但活动审计仍完整。
4. 最后复读目标，再 `_commit(records, [], archives=references)`：验证历史，编码，
   在队列同目录创建唯一临时文件，写入/flush/fsync，再检查文件/源/归档链，最后 os.replace。
   只有替换成功后才更新内存；归档将该段异常报告为 archive_commit_unconfirmed。
   临时文件仅在身份仍匹配时清理，其他证据不自动删除。
5. 重开读取 version 4 中的引用及空活动审计；重放同参数返回 replayed。
   归档不改事件 ID、绑定、业务状态、revision、累计 attempts 或 retry_grants。
   替换后响应丢失必须重开判断，不能用异常推断事务未提交。

## D. 容量与归档核验

默认限制保持 32 个索引、单文件 131072 字节、累计 2097152 字节；快照默认 2 MiB，
活动审计 256 条且不超过 min(64 KiB, max_bytes/4)，告警总量与高危预留未调整。

新增中断测试使用 max_audit_records=1：提交前活动审计 1 条、归档引用 0，
提交后活动审计 0、引用 1；历史审计仍能读取，records（含事件身份/次数）逐字段一致。
失败未提交时源字节和文件身份与登记值一致；提交后响应失败重开得到相反的正确结果，
即已提交、活动审计为 0。同 UUID 重放快照身份及摘要不变。

单文件测试在 131071/131072 字节成功完成存储层写入复读，131073 字节在创建前拒绝。
其填充审计行故意不满足领域契约，queue.audit_status 仍拒绝，不能将存储层校验成功当作
可信归档。不是使用合法活动审计制造 128 KiB 记录的证据。

真实文件链测试使用真实文件身份、规范 JSON、SHA-256、合法审计行和历史校验，
仅替换 secure_output/_permissions 的平台 ACL 工具调用，避免重复启动大量 PowerShell。
另一个算术测试用模拟引用验证实际常量：31×65536 + 65537 = 2097153 字节拒绝；
32 个引用时拒绝新增，并核对源不变。模拟引用不代表已持久化的可信归档链。
真实文件链的实测用量登记在 `full-isolated/test_real_files_reach_bounded_0/capacity-results.json`
与相邻 `_1` 场景，专项两轮和全量得到相同数值：

剩余容量或检测未指定的准备文件。没有自动回收、自动删旧链或无限轮转能力。
