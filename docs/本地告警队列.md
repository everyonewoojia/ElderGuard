# 本地持久告警队列与生产 Reporter

默认启动在设备凭证和公开绑定齐备时创建持久 Reporter，由 Agent 管理唯一
异步发送任务。`simulate_attempt` 仍仅供假发送器测试，不能置为 `received`。
云端按设备与 event_id 幂等接收（见接口契约）；本地接收证据与云端通知结果
分别保存，不代表家属实际收到或确认，不保证严格一次送达。

## 配置与调用链

沿用 `ELDER_DATA_DIR`、`EDGE_BASE_URL`、`EDGE_ELDER_ID`，新增非秘密配置
`EDGE_DEVICE_ID`（登记设备 ID）。设备 ID 必须显式配置，不能从 JWT 推断。
设备 JWT 仍由 EdgeClient 读取受保护的凭证文件，不进入本队列。

`create_agent → AlertOutbox + EdgeClient + EdgeReporter → ElderAgent`；
`_publish_event → enqueue → EventBus → AlertPlugin → Reporter.wake → claim → EdgeClient → 云端 → 回执原子写回`。
Reporter 与 Agent 必须使用同一个队列对象，客户端的规范化地址必须匹配队列绑定。
设备 ID 配置不取自未验证 JWT；云端认证决定实际设备，回执设备 ID 必须匹配本地绑定。
Agent 在异步分发之前生成 UUID4 并同步完成原子保存，避免排在插件前面的
订阅者挂起后，停止或取消导致事件尚未入队。直接交给插件的无 ID 事件由
插件补充一次；已有 ID 不替换。插件仍核验同一队列中的记录，同一 ID 的
业务字段相同则复用，不再次写盘；字段冲突则拒绝覆盖。

事件总线逐个 await 订阅者，返回正常返回、拒绝及异常计数；这些计数只代表
分发情况，不代表持久化或云端接收。Agent 告警返回结果分别包含 `published`、
`persisted` 和未知的 `cloud_received: null`。保存失败不会开始分发，插件异常
向 Agent 调用者报告处理失败；已保存的记录不会被抹掉。

停止时先拒绝新事件，取消并等待主循环，再停止 Reporter，最后关闭自有 HTTP
客户端和队列。Reporter 先停止新认领，有界等待后取消；若两轮等待均超时，
保留任务句柄、客户端及队列锁，不虚报已关闭，允许后续重试停止。同步入队段
没有 await，正常停止和 asyncio 取消不能在其内部交付；后续分发或 TTS 可
被取消，但已入队记录保留。停止不等待外部调用者创建的全部分发/TTS 任务，
调用者仍需管理这些任务。直接绕过 Agent 调用 EventBus 不具有分发前入队保证。
意图识别完成前、入队尚未执行或原子保存完成前突然终止/断电不保证可恢复。

没有设备 ID 时，不创建持久队列，插件返回持久化失败并保留本地提示；
明确配置但队列损坏、绑定不符或所有权无法确认时，拒绝创建 Agent。
没有凭证不影响独立本地保存，但隐私策略仍按既有规则关闭采集。
本地绑定只是保存目标，不替代服务端设备认证和老人归属校验。

队列保存失败时，Agent 独立调用本地 TTS 提示未能保存，不发布或发送告警。
TTS 返回 False 或抛出异常时记录受控失败类别，不宣称播放成功。
非告警事件（例如提醒、时间、普通指令）正常分发，但不进入告警队列。
EdgeClient 与旧 Reporter 要求调用者显式提供稳定 event_id，重试保留该值；
无 Outbox 的旧 Reporter 直接调用接口保留原兼容行为，但默认生产启动不使用它。
生产模式不创建其内存待发/失败列表，也不在每条告警到达时创建任务。
Agent 启动先沿用既有隐私同步与安全 ASR 初始化，再启动插件及 Reporter；
启动扫描已有待发记录，新记录通过事件唤醒或有限轮询发现。插件在 TTS 前
唤醒 Reporter，语音失败不删除或阻止已保存告警发送。

## 文件、状态与容量

队列为数据目录下独立的 `alerts_outbox.json`，不与 `user_profile.json` 共写。
普通写入格式为 `version: 3`、设备/老人/规范化云端地址 `binding`、`records` 和有界 `audit`。
第一次归档后为 version 4，另含有界的 `archives` 证据引用。
可读原 version 1/2/3 快照，保留记录和次数；旧版本正常写入升级为 version 3，
不重置队列。旧程序不应继续写新版快照。
每条记录只含事件 ID、绑定、告警类型、优先级、必要内容、发生时间、
状态、尝试次数、下次尝试时间、受控错误类别/状态码及云端告警 ID、通知状态、
未确认状态。只有有效接收回执才填写云端字段；它们是当次回执快照，不是实时通知查询。
不序列化完整事件、JWT、Authorization 头或原始异常文本。

`help/fall/abnormal` 保持同名映射；优先级只接受 `P0/P1/P2`。
内容只提取 `payload.content`，缺失时使用对应类型的固定描述。
状态为 `pending/sending/blocked/exhausted/failed/received/resolved`。初次加三次重试，
初始最多四次认领；每份明确人工重排授权增加一次额度，累计次数不重置。
失败退避为 `min(60, 2**attempts)` 秒，次数与时间持久保存。
中断的 `sending` 在重开时恢复为待处理或耗尽，并保留原事件 ID。

| 观测结果 | 本地处理 |
| --- | --- |
| 严格匹配的有效回执 | `received`，保存 alert_id、notification、unconfirmed |
| 网络错误、5xx、非法或不匹配回执 | 退避到 pending，达到四次后 exhausted |
| 401/403 | blocked，不自动恢复 |
| 409 | failed/conflict，不换新 ID |
| 422 | failed/invalid_payload，不盲目重试 |
| 其他 4xx | failed/request_rejected |

成功必须同时满足 HTTP 200/201、统一响应结构、正整数 alert_id、原 event_id、
当前 device_id、received、合法通知字段与 unconfirmed，不能仅凭 200 或非空对象。
notification=unknown 仍可证明云端已接收，不能证明通知送达。云端提交后响应
丢失或本地写回失败，原记录保留；后续沿用原 ID 请求，由云端幂等记录核对。
写盘失败会停止该队列实例写入，须关闭后重新打开核验。最后一次响应丢失仍
可能留下 exhausted 记录，需要人工核对。blocked/failed 不自动解除；
received/blocked/failed/exhausted/resolved 不自动重发。

默认上限 1000 条、UTF-8 快照 2 MiB；其中 100 条和 256 KiB 留给 P0
或 help 告警。另为每条记录预留 128 字节状态转换空间，实际可接纳量
因此可能更小。达到限制时明确拒绝新记录，不淘汰旧告警。

## 所有权、原子保存与边界

一个数据目录只允许一个活动队列实例持有内核锁：Windows 使用
`msvcrt.locking`，POSIX 使用 `flock`。锁文件存在不代表进程存活；不删除
所谓的过期锁文件。正常关闭释放锁，异常终止由操作系统回收描述符。
Agent 只关闭自己拥有的队列；注入队列由调用者关闭。

验证目录和已有文件的 OS 账户归属、规范化路径、链接/重解析点及文件系统
身份；写入前再次验证，并核对快照摘要以发现原地改写。无法验证则拒绝。
在同目录写入唯一临时文件，flush/fsync 后原子替换；失败不清空旧队列，
实例停止写入，待重新打开核验。仅清理本次创建且身份仍匹配的临时文件，
从不递归删除数据目录、未知文件、旧队列或锁文件。

正常断电耐久性取决于文件系统；文件 fsync 与原子替换不承诺所有断电场景。
Windows 路径校验与实际操作之间仍有竞态窗口。身份检查、摘要和内核锁可
防止普通误用与合作进程冲突，不能隔离同一 OS 账户下恶意替换目录的进程。
应使用当前账户专属、访问权限受控的本地数据目录。检测到不一致时停止操作，
不声称仅靠路径检查彻底消除了竞态。

本地保存成功只反馈“本机保存，目前无法确认家属收到”；保存失败明确提示
“未能保存”并建议其他求助方式。不宣称云端接收、推送发送或家属送达。

## 保留、容量治理与人工核对

保留期集中定义为 `AlertOutbox.RETENTION_DAYS=30`。只清理收到有效回执后满
30 天的 received，或明确人工终结后满 30 天的 resolved；使用终态证据时间，
不使用原事件发生时间。旧快照缺少终态时间时不猜测年龄，须核对或处置后
才有清理依据。pending/sending/未解决 blocked/exhausted/failed 永不因年龄淘汰。

新事件入队前机会性清理，每批最多 32 条；显式 prune 也使用同一规则。删除
记录与清理审计在一次原子替换中完成，无第二份归档文件。保留快照摘要的
清理计划和每条事件审计；已清理事件的重放会被拒绝，避免复活人工终结记录。
清理后重新核算原条数、字节数及 P0 预留限制，仍满则明确拒绝保存，不发送
HTTP。查询同时报告实际文件字节数与下一次写入预计字节数。

审计不保存正文或凭证；上限 256 条且不超过 `min(64 KiB, max_bytes/4)`，仍计入
原快照总字节限制。审计满时拒绝新增人工决策或删除，不滚动丢弃旧证据。
可显式导出并核验归档以恢复活动审计容量，见下节。归档不释放告警条数，不改变
事件 ID、绑定、载荷、重试次数、业务状态或终态时间，也不会触发 HTTP。

本地管理入口（工作目录 elder-agent）：

```text
python -B -m src.integration.outbox_admin --outbox ABSOLUTE_ALERTS_OUTBOX_JSON --device-id DEVICE --elder-id ELDER --cloud-url CLOUD_ORIGIN [--token-file ABSOLUTE_CREDENTIAL_FILE] COMMAND
```

必须停止持有该队列锁的 Agent，包括只读查询；命令不会寻找队列、创建空快照、
接管活动锁或暗中恢复 sending。目录/文件及公开绑定沿用原身份检查。
本地主机账号及目录 ACL 是权限边界，operator 是审计署名，不是认证凭据。

| COMMAND | 行为 |
| --- | --- |
| `list` | 状态数量、条数/字节/P0 预留、审计用量和 snapshot_digest |
| `show --event-id UUID` | 必要元数据和该事件审计，不显示正文 |
| `check --event-id UUID` | 只读认证 GET；不修改快照，不执行 POST |
| `reconcile` | 云端存在且设备、事件、哈希、回执匹配时，原子更新 received 和审计 |
| `retry` | 先查云端；存在则核对为 received，未找到且本地 blocked/exhausted 才可重排 |
| `resolve` | 明确终结 pending/blocked/exhausted/failed，不将处置当作云端接收 |
| `prune` | 先输出候选，按摘要核验后清理符合保留期的记录 |

reconcile/retry/resolve 都要求 `--event-id UUID --confirm-event-id UUID
--expected-revision REV --operation-id OP_UUID --operator ADMIN --reason REASON`。
原因码为 reviewed、credentials_repaired、cannot_repair，不接受可能夹带凭证的
自由文本。修订号来自 show；网络查询后不自动刷新修订号，变化即拒绝覆盖。
同一操作 UUID 和参数重试返回原审计，既不增加额度，也不创建发送任务。

prune 要求 `--confirm --expected-digest DIGEST --operation-id OP_UUID --operator ADMIN
--reason retention_expired`。摘要来自 list；旧摘要拒绝。同一操作重放返回历史
计数并标记 replayed，不表示本次又删除了记录。审计与删除同快照，写入中断后
只能看到旧快照或完整新快照；失败响应不保证提交未发生，须按原操作 UUID 核对。

401/403 后必须通过当前设备 JWT 的 GET 实际验证启用状态、凭证版本及老人归属，
仅换凭证文件不足以解除阻塞。查询失败或认证拒绝不会修改记录，也不当成
not_found。not_found 只表示当前时刻未发现该设备的接收记录；人工重排仍使用
原事件和原载荷，由原 Reporter 执行，后续并发提交依靠云端幂等保护。

409/422 等永久 failed 不允许直接重新排队，只能调查、核对已接收证据或明确
resolve；不编辑载荷、迁移绑定或更换 ID。云端哈希不匹配拒绝更新并报告
payload_conflict。设备吊销或绑定失效时，GET 也必须拒绝，不提供历史读取后门。

## 审计导出、归档及中断恢复

沿用上述完整命令前缀，先停止 Agent、取得同一 OS 锁。不要删除锁文件。
所有路径都须为显式、规范化绝对路径；目录必须已存在且属于当前 OS 账户。
以下占位符不是实际路径或凭证：

```text
list
audit-export --destination ABSOLUTE_NEW_EXPORT_JSON
audit-archive --destination ABSOLUTE_NEW_ARCHIVE_JSON --expected-digest REVIEWED_SOURCE_SHA256 --operation-id OP_UUID --operator ADMIN --reason reviewed
audit-status --destination ABSOLUTE_ARCHIVE_JSON
```

`list` 只读报告活动审计条数及字节上限、队列字节、状态转换预留、P0 预留占用、
历史归档数量及核验状态。`capacity_blocks` 区分 audit_count_full、audit_bytes_full、
queue_bytes_full、transition_reserve_insufficient 和 urgent_reserve_in_use；这些是当前
用量边界，不是下一条任意大小审计或告警必定能写入的保证。未到上限也可能装不下
下一条记录。审计满仍可 list/show/check 和导出；普通 prune 不绕过审计限制。

导出文件是规范化 UTF-8 JSON：格式版本、设备/老人/云端绑定、源快照 SHA-256、
导出时间、活动审计、审计数及其内容摘要。摘要基于 sort_keys、紧凑分隔符、
ensure_ascii=False、禁止 NaN 的 JSON。只导出审计，不复制告警正文或任何凭证。
导出后复读校验内容和文件身份，返回 export_verified；源快照字节和容量不变。
这仅证明导出通过验证，并不表示本地归档事务提交或容量已经恢复。

目标使用 OS 独占创建，拒绝覆盖已有文件、源队列、锁文件、已引用归档及路径别名。
Windows 备用数据流、保留设备名等路径也在文件操作前拒绝。
写入任何审计字节前设置私有权限：Windows 使用当前用户专属 DACL 并复核，POSIX
使用 0600。权限工具不可用即拒绝。失败或中断留下的输出不自动删除或覆盖，须核对。

归档要求 list 中人工审核的 snapshot_digest，并使用固定操作 UUID、署名和受控原因。
先完整保存当前活动审计到独立文件，flush/fsync 并复读核验，再将该文件的绝对路径、
原始文件及父目录身份、文件摘要、条数、源摘要、操作 UUID、署名、原因、前归档摘要
与空活动审计一起原子提交到源快照。新引用也计入原总字节上限，并保留每条告警
128 字节状态转换空间；放不下时报 archive_marker_capacity，源审计不减少。

成功返回 archive_committed。随后 list 应显示活动审计减少、archive_status=verified；
实际空余仍受总字节、告警条数及 P0 预留限制。归档不是“告警空间已经清空”。
核对无误后方可正常恢复 Agent；Reporter 沿用原记录及次数，不因归档重发终态告警。

`audit-status` 只检查显式文件，不扫描目录：archive_prepared 表示证据已生成且匹配
当前源，但尚未提交；archive_committed 表示源引用和文件均已核验；archive_stale
表示文件与当前源不能作为同一次待提交操作恢复。单纯导出返回 export_verified。
prepared 时使用原路径、摘要、UUID、署名及原因重试可继续提交，不覆写证据。
重试会对既有准备文件重新执行 fsync 并核验身份和摘要；刷盘失败返回
archive_sync_failed，不释放源审计容量，不能因文件可以读取就推断已安全保存。
committed 时同参数重试返回 replayed，不再次释放容量；同 UUID 不同参数拒绝。
原子提交异常返回 archive_commit_unconfirmed，不能据此推断提交没有发生；关闭并重开
后先 status，再按原参数核对。源在此期间变化时拒绝继续采用旧证据，不自动刷新摘要。
不完整或权限未建立的输出不能原位覆盖重试。先人工确认源未提交、审计完整，再选择
新的显式目标及新操作 UUID；原输出保留待核对，不由命令自动删除。

归档链每次修改前重新验证。历史操作 UUID、人工重试额度与清理防重放仍从所有已验证
归档读取。缺失、替换（即使内容相同）、改写、父目录变化、ACL 放宽或摘要不符时
拒绝相关修改；队列重开核验也拒绝，不重建证据或自动清理。运行中 list 可报告受控
archive_* 错误；启动即拒绝时 CLI 返回非零错误码。保留原路径和文件身份，不要搬移
归档。仅恢复同一原始对象到原路径才可能重新通过身份检查；其他灾备恢复须另行审核。

索引最多 32 个归档，单个最多 128 KiB，累计最多 2 MiB；引用仍占队列空间。
达到任一限制时报 archive_capacity，不自动删除历史链或丢弃 UUID 证据。
这提供有界的维护窗口，不是无限轮转；达到全链上限需要另行设计、审核维护方案。
未完成或失败输出也必须由运维核对和管理磁盘空间，本工具不自动扫描删除。

摘要与身份可发现普通误用、改写和合作进程冲突，不提供抗同账户恶意篡改的签名证明。
Windows 校验与打开/创建/替换之间仍存在 TOCTOU；没有声称完全消除并发路径替换。
文件 fsync 与原子替换也不保证所有断电情况下的目录项耐久性。应使用受控本地目录、
专属 ACL 和可靠备份；归档及父目录必须长期保留，避免人工改名、替换或清理。

## 部署前恢复操作清单（2026-10-18 演练补充）

先在启动 Agent 的终端请求正常停止（例如 Ctrl+C），等待 `agent.stop()` 完成，
确认服务管理器不会自动重启。停止超时不能视为锁已释放；CLI 报 owner_busy 时停止维护，
不要删除锁或强行接管。恢复时从原部署工作目录、原 OS 账户和原配置启动；本轮演练不启动真实 Agent。

以下 PowerShell 示例在 `elder-agent` 下执行。必须先将占位符替换为经过人工核对的
绝对路径和公开绑定，不能从 JWT 推断。维护归档不需要 `--token-file`。

```powershell
$py = (Resolve-Path ../.venv/Scripts/python.exe).Path
$queuePath = 'C:\REVIEWED_DATA_DIR\alerts_outbox.json'
$archivePath = 'C:\REVIEWED_ARCHIVE_DIR\new-archive.json'
$exportPath = 'C:\REVIEWED_ARCHIVE_DIR\new-export.json'
$prefix = @('-B', '-m', 'src.integration.outbox_admin', '--outbox', $queuePath,
    '--device-id', 'REVIEWED_DEVICE', '--elder-id', '1', '--cloud-url', 'https://REVIEWED_HOST')
& $py @prefix list
if ($LASTEXITCODE -ne 0) { throw '停止维护，核对路径、绑定、权限和队列所有权' }
& $py @prefix audit-export --destination $exportPath
if ($LASTEXITCODE -ne 0) { throw '保留输出，先检查失败原因' }
# 人工审核 list 输出中的 snapshot_digest；固定本次 UUID，记录后不得随意更新。
$reviewedDigest = 'REVIEWED_SNAPSHOT_SHA256'
$operationId = 'RECORDED_OPERATION_UUID'
& $py @prefix audit-archive --destination $archivePath --expected-digest $reviewedDigest --operation-id $operationId --operator local-admin --reason reviewed
# 即使上一命令报错，也先另开队列核验，不能凭退出码判断提交未发生。
& $py @prefix audit-status --destination $archivePath
& $py @prefix list
```

`audit-status` 必须带显式目标：文件尚不存在时返回 archive_missing，不是“初始正常”状态。
初始活动审计用 `list` 检查。每个 CLI 命令退出后会关闭队列；重开仍报 owner_busy
说明所有权未确认，应停止操作。不要使用目录扫描结果推断某个文件已被引用。

| 重开后的结果 | 处置与验收 |
| --- | --- |
| export_verified | 仅导出；源快照字节、身份及活动审计用量不变，不恢复容量 |
| archive_prepared | 文件与当前源匹配；不证明此前 fsync 成功，仍未释放活动审计；核对原路径、UUID、摘要、署名和原因后按原参数重试，程序重新刷盘 |
| archive_committed | 引用和证据均核验；再用 list 确认 archive_status=verified、活动审计减少，show 核对事件 ID、revision、attempts 与维护前一致 |
| archive_stale / revision_conflict / operation_conflict | 停止自动重试，保存证据，人工核对源是否变化及参数是否冲突 |
| archive_write_failed / archive_sync_failed | 不根据可读性判断刷盘成功；重开 status，完整 prepared 可按原参数恢复，不完整输出保留且不得原位覆盖 |
| archive_commit_unconfirmed / 通用未确认错误 | 可能已经替换成功；关闭后重开 status/list，committed 按原参数重放，prepared 经审核后继续；不能在未核对前改 UUID 或执行删除 |
| archive_missing / archive_invalid / archive_identity / archive_permissions | 保留源、目标和原目录身份；不修改、不搬移、不重建历史文件，升级人工审核；启动即失败时 status 也可能无法执行 |
| archive_capacity / archive_marker_capacity / audit_capacity / capacity | 记录错误、list 用量、目标状态和限制，停止增加操作；不删除旧归档腾空间，不减少身份校验；完整准备文件仍可能因容量不足无法提交 |

`audit-status` 报告文件阶段，`list` 报告活动审计/快照容量，错误码报告拒绝原因，
三者应联合判断；status 不是剩余磁盘容量探测器，也不会自动找到孤立准备文件。
容量确认必须比较维护前后的 audit_records/audit_bytes/audit_byte_headroom、archive_count、
bytes/next_write_bytes、transition_reserve_bytes 和 capacity_blocks。审计空列表本身也占字节；
索引新增引用可能使快照比维护前更大。不得只凭 archive_committed 推断下一次任意操作可写。

维护前登记队列及目标的规范化路径、文件身份（设备号/inode）、SHA-256、公开绑定、
事件元数据、修订号、操作 UUID 和参数；目标不存在也要登记。维护后记录相同指标、
退出码和受控诊断。故障原件留在原路径，不为收集证据而移动或覆盖；另外保存的副本
必须标为参考副本，不能替代原身份。备份和证据中仍不得加入 JWT、认证头或业务正文。

无法验证的旧归档、未知准备文件、所有权不明、索引耗尽、ACL 异常、关闭失败或源变化
都应停止修改并人工审核。未经核验的准备文件和历史归档不得直接删除；不得因索引满
而手动删证据规避限制，不得重新生成事件 ID 绕过幂等。人工恢复方案超出当前 CLI 能力时
必须另行设计审核，不能改写快照或把 unknown 转为成功。notification 尝试结果仍不代表
家属已收到或确认。断电、硬件故障和恶意并发路径替换没有自动恢复保证。

本轮可执行证据及模拟边界见 [归档恢复演练验收](归档恢复演练验收.md)。
