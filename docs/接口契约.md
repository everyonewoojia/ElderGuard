# 银发守护 · 接口契约（v1.0）

> 本文档依据《空巢老人智能看护（银发守护）架构设计文档》第 9 章固化，供三端（老人端、云端、家属端）对齐联调用。所有实现与测试均以此契约为准；修改需同步更新本文档及对应契约校验测试。

## 1. 通用约定

- 基础路径：`/api/v1`
- 认证方式：JWT Token（请求头 `Authorization: Bearer <token>`）
- 统一错误码：`400` 参数错误、`401` 未鉴权、`403` 越权、`404` 不存在、`500` 服务异常
- 家属 REST 成功响应按路由返回数组或业务对象，不统一包络；
  老人端接收回执等明确约定包络的接口仍使用以下格式：

```json
{ "code": 200, "message": "success", "data": {} }
```

## 2. REST 接口

### 家属小程序 REST 响应（P1-01，2026-10-18）

以下路径均相对于 `/api/v1`，成功状态均为 HTTP 200：

| 接口 | 实际成功 JSON | 小程序消费方式 |
| --- | --- | --- |
| `GET /elder` | `ElderResponse[]` | 首页、设置页直接读取数组首项 |
| `GET /tasks` | `TaskResponse[]` | 首页直接读取数组，按当前 elder_id 筛选 |
| `GET /alerts` | `AlertResponse[]` | 告警页读取完整数组；首页取前三项 |
| `GET /elder/{id}`、`GET /alerts/{id}` | 单个业务对象 | API 工具原样返回；老人详情页使用前者 |
| `POST /tasks` | 新建任务对象 | 设置页成功后提示并清空表单 |
| `POST /privacy/auth` | `{message, enabled}` | 设置页成功后更新开关 |
| `POST /alerts/{id}/cancel` | `{message}` | 告警页成功后重新查询列表 |
| `POST /auth/login` | `{access_token, token_type}` | 登录页直接读取令牌对象 |

`utils/api.js` 仅去掉微信传输层的 `res.data`，将 HTTP 响应体原样交给调用者，
不再额外包装或解包业务字段。合法对象及其他接口的既有包络保持原样。
列表成功但无数据时返回 `[]`；首页、告警页显示空列表，设置页无绑定老人。
再次获取到空老人列表时清除旧绑定；首页同时清除依赖旧绑定的列表与用药计数。

HTTPException 错误仍返回 `{code, message, data: null}`；401 跳登录并拒绝请求，
403 等非 2xx 拒绝请求并保留服务端错误消息；网络失败原样拒绝，不转换为 `[]`。
页面沿用现有 catch 路径（不更新已加载数据，尚无统一网络错误提示）。
FastAPI 参数验证错误仍为 422 的 `detail` 结构，不属于列表成功数据。

`tests/test_miniapp_rest_contract.py` 在既有受保护临时数据库中调用真实路由，
将合成响应的状态码及 JSON 通过子进程环境变量直接交给 Node 页面测试；
后者加载实际页面与 API 工具，仅模拟微信运行时，不改写云端响应体。
独立 `npm test` 使用相同数组/对象结构的合成样例；这不等同于微信终端或公网部署验收。

P1-03 路由完整性：保留 `/pages/elder/detail` 和 `/pages/tasks/tasks`，补齐页面文件。
首页详情入口仍不传 URL 参数；两页不定义额外查询参数，收到未定义参数显示参数错误。
优先使用应用当前选中的老人 ID，否则 GET /elder 取首个绑定；无绑定为正常空状态。
详情复用 GET /elder/{id}；任务页只读 GET /tasks，并按 elder_id 筛选，不新增创建、删除或导航入口。
任务页目前只有路由声明，保留作最小兼容入口；创建任务仍在原设置页。
两页区分加载、空数据和错误，复用原 401/403 行为；页面隐藏/卸载、刷新、账号或老人变化
使旧请求失效，加载期间选中老人改变时改为加载最新范围。文件与 Node 页面测试不代表真机验收。

### 家属认证安全配置与撤销（2026-10-18）

家属 JWT 的 `SECRET_KEY` 必须显式配置，不再提供可用的开发默认密钥。
应用 lifespan 在启动工作者前验证配置；签发和验证 JWT 时也再次验证。
模块导入仅构造设置，不因缺少该值而阻断无关模块导入；缺失值不能用于启动认证服务。
空值、首尾空白、已知开发占位值、短于 32 个 UTF-8 字节、少于 16 种字符，
或与 `EDGE_JWT_SECRET` 相同的值均拒绝。长度和字符检查不证明随机性，部署仍须使用
安全随机生成的独立密钥。错误只报告配置项无效，不回显值。

测试基座在导入应用前显式生成两份独立合成密钥，并阻止读取部署 `.env`；
这不是生产环境回退。家属密钥轮换后，旧密钥签名的 JWT 无法验证，包括现有 WS 的复核。
设备 JWT 的签名、用途、版本和绑定策略不变，不能与家属 JWT 混用。

停用账号登录返回 401；停用账号使用原 JWT 调用受保护 REST 也返回 401。
REST 每次查询当前账号，家属业务继续检查当前角色和老人归属。
家属 JWT 必须包含有效的 `sub`、整数 `exp`，缺失或到期均拒绝。

WS 路径为 `/api/v1/ws/alerts`，新增 `Authorization: Bearer <JWT>` 握手 Header；
原 `?token=...` 仍兼容旧客户端。接受连接前验证当前账号启用状态和
家属角色；存续期间默认每 1 秒复核，停用、角色失效、JWT 到期或校验异常时关闭 4401
并移除连接登记。每次历史补推及工作者发送前再次核验账号、令牌及当前老人归属，
校验结束后关闭短 Session，再执行发送，不在整个连接生命周期持有 Session。
发送由连接管理，默认 1 秒超时并取消可配合取消的发送，避免它无限占住撤销检查。
接收超时任务由当前路由等待/回收，不创建独立轮询后台任务。

在事件循环和数据库正常响应、ASGI 发送配合取消的前提下，空闲连接在下一次 1 秒复核
关闭；正在发送时还可能等待最多 1 秒发送超时及校验/调度开销。每次新发送都有即时复核，
不能以尚未到定时检查点为理由绕过授权。同步数据库阻塞或不配合取消的底层传输没有
硬实时关闭保证，部署需监测并终止异常进程。已开始的发送不能与账号停用事务原子撤回，
关闭连接也不能撤回此前已交付的数据。WS 令牌 URL、TLS 和代理日志风险仍属后续事项。

| 接口 | 方法 | 说明 | 鉴权 | 优先级 |
| --- | --- | --- | --- | --- |
| `/auth/login` | POST | 家属登录鉴权 | 否 | P0 |
| `/elder/{id}/logs` | GET | 查询老人监护日志 | 是 | P0 |
| `/tasks` | POST / GET | 创建、查询提醒任务 | 是 | P0 |
| `/tasks/{id}` | DELETE | 删除提醒任务 | 是 | P0 |
| `/alerts` | GET | 查询历史告警记录 | 是 | P0 |
| `/alerts/{id}/cancel` | POST | 取消误告警 | 是 | P1 |
| `/privacy/auth` | POST | 修改隐私授权开关状态 | 是 | P0 |
| `/health` | GET | 健康检查（非业务） | 否 | — |

所有家属接口必须携带鉴权令牌；服务端校验家属与老人的绑定关系，越权访问返回 `403`。

### 2.1 老人端告警幂等接收

`POST /edge/alerts` 使用独立设备 JWT，不能使用家属 JWT。服务端先验证设备
启用状态、凭证版本和当前老人/家属绑定，再查询接收记录；请求体 `device_id`
不作为身份依据。`GET /edge/tasks`、`/edge/settings`、`/edge/privacy` 的设备认证保持不变。

请求字段：`elder_id`、必填 `event_id`、`alert_type`（help/fall/abnormal）、
`priority`（P0/P1/P2，默认 P1）、`content`（可空，最多 4096 字符）。
`event_id` 是客户端在入本地队列前生成的规范小写带连字符 UUID，重试必须沿用；
缺失、格式错误返回 422，服务端不补造 ID。当前请求不包含事件发生时间。

幂等键为数据库唯一约束 `(认证设备 device_id, event_id)`。确定性 SHA-256
输入为可信 `elder_id`、`alert_type`、`priority`、`content` 的排序紧凑 UTF-8 JSON；
缺省值先展开，null 与空字符串不同。凭证、未知字段不参与哈希或接收记录。
同键同载荷返回原 alert_id，同键不同载荷返回 409，不覆盖历史记录。
不同设备有独立命名空间；跨老人请求在接收查询前拒绝。

成功响应沿用 `{code,message,data}`，data 示例：

```json
{
  "alert_id": 1,
  "status": "pending",
  "event_id": "b0befb9b-c06e-4b41-94a7-2afba2d73491",
  "device_id": "registered-device-id",
  "receipt_status": "received",
  "notification": "pending",
  "notification_attempts": 0,
  "notification_send_count": null,
  "notification_last_result": null,
  "confirmation": "unconfirmed"
}
```

`receipt_status=received` 仅在 AlertLog、EdgeAlertReceipt 及其 `pending` 通知状态同事务提交确认后返回。
数据库异常或提交结果不确定返回 503，客户端应保留原 ID 重试。
`status` 保留现有家属告警状态语义，不能用它推导家属实际确认。

HTTP 请求只负责接收事务，不等待外部发送。`notification` 是持久通知状态：

| 状态 | 证据及后续处理 |
| --- | --- |
| `pending` | 已持久化，尚未认领；服务重启后仍可处理 |
| `sending` | 条件更新认领已提交，具有认领标识和租约；不代表已发送 |
| `attempt_returned` | 发送函数正常返回；保存真实返回计数，0 也不代表送达 |
| `retry_wait` | 在调用发送之前明确发现无本进程在线连接，按退避时间重试 |
| `attempt_failed` | 明确未发送的尝试达到当前额度，不再自动重试 |
| `unknown` | 可能存在外部副作用，结果无法确定；不自动重发 |
| `cancelled` | 家属已取消且任务尚未开始发送，不再认领；不改变 AlertLog 的原状态语义 |

`notification_attempts` 是已提交认领次数；`notification_send_count` 是发送函数
正常返回的计数（无此证据时为 null）；`notification_last_result` 为 null、
`claimed`、`returned`、`not_started` 或 `unknown`。这些字段均不能证明终端收到。
重复 HTTP 请求返回同一接收记录的当前持久状态，不增加任务或重置状态。
`confirmation` 始终是 `unconfirmed`，本阶段不提供家属确认业务。

工作者使用 SQLite 条件 UPDATE 竞争认领，在短事务提交后才调用 WebSocket，
发送期间不保留 SQL Session。默认租约 30 秒、发送超时 5 秒；只有原认领标识
且租约仍有效时才允许写回。发送异常、超时及过期的 `sending` 保守记为
`unknown`；结果写回失败保留 `sending`，过期后再恢复为 `unknown`。
只有明确在发送前失败的任务可重试，退避为 2 的尝试次数次幂秒（上限 30 秒），
初始最多认领 3 次；每次持久人工重试授权额外增加 1 次额度，不重置累计次数。
离线时不认领。不存在跨数据库与 WebSocket 的严格一次送达保证。

FastAPI lifespan 保留单个工作者句柄，启动只读核验结构，不执行 DDL；停止时
先停止新认领，有界等待后取消在途操作。不可恢复的数据库错误会传播。
连接登记仍在进程内，只有具有本地在线连接的工作者认领对应家属任务；
本阶段未实现多实例连接路由或消息代理。`unknown` 的受控本地恢复见下文。

老人端默认启动现通过持久 Reporter 发送已原子入队的告警。只有 HTTP 成功、
统一包络及设备/事件匹配的完整接收回执通过校验，并成功写回本地 Outbox 后，
本地记录才成为 `received`；云端 notification=unknown 与此接收事实相互独立。
网络、5xx 或响应丢失重试同一 event_id，初次加最多三次重试；401/403 阻塞，
409/422 和其他永久 4xx 保留失败记录，不更换事件 ID。回执写盘失败不删除原
记录，重新打开队列后依靠幂等请求核对。详见 [本地告警队列](本地告警队列.md)。

### 2.1.1 设备回执只读核对

`GET /edge/alerts/receipts/{event_id}?elder_id=ID` 继续使用独立设备 JWT 与当前
设备登记/老人归属校验。先校验绑定，再按 `(认证设备ID,event_id)` 查询已有
EdgeAlertReceipt；请求者不能选择其他设备命名空间。无迁移、无建表、无提交
写入、无通知调用，不重置通知状态。结构缺失等数据库错误返回受控 503。

查到时返回原 POST 回执字段及 `payload_hash`，不含告警正文或额外老人信息。
哈希规范仍是 elder_id/alert_type/priority/content 的排序、紧凑、ensure_ascii=False
UTF-8 JSON 的 SHA-256；空字符串、空白和 null 不互相转换，凭证不参与哈希。
未找到时返回 200，data 为 `{event_id,device_id,receipt_status:"not_found"}`；
这不保证并发请求稍后不会提交。认证错误是 401/403，查询异常是 503，均不能
被客户端当作 not_found。云端存在但本地哈希不同必须保留冲突，不补造事件 ID。

本地 check 不改状态；reconcile 只有身份、哈希及完整接收回执均匹配时才写入
received。notification=unknown、confirmation=unconfirmed 保持原语义，不代表送达。
本地 retry 只有在认证查询未找到后才可明确授权，不能改变云端通知 unknown。

### 2.2 显式接收表与通知字段增量迁移

受信任本地管理员从 cloud-server 执行：

```text
python -B -m scripts.migrate_edge_alert_receipts --database ABSOLUTE_SQLITE_FILE
```

DATABASE_URL 必须配置为与参数相同的绝对 SQLite 文件。命令核验应用配置、
原 engine/Session 工厂对象、实际 Session 绑定、路径和文件身份，再创建
`edge_alert_receipts` 及其唯一约束、外键。已有旧接收表只增加缺失通知字段及
通知状态/退避时间索引；已有同名字段、表和索引必须符合预期结构。
`schema_migrations` 记录 `edge-alert-delivery-v1`，只在完整结构核验后写入版本。
本轮另增 `notification_revision` 和 `notification_recoveries` 审计表及其索引，
记录版本 `notification-recovery-v1`；旧接收记录修订号为 0，不改变原通知事实。
旧接收记录新增通知状态为 `unknown`，不补造已发送证据或待发任务；
无接收记录的历史告警不补造事件 ID 或接收记录。
应用启动不会执行该迁移。重复执行核验结构和版本，不重建业务表，
不修改历史告警。部分 DDL 成功后中断时保留现场，重跑可补齐缺失字段，
不删除表补救。此命令的自动化验证仅在 P0-12 登记的临时数据库中进行。
管理员负责配置与父目录访问权限；路径检查不能防御同账户恶意并发替换。

### 2.3 本地通知运维与健康检查

本地受信任管理员可运行 `python -B -m scripts.manage_notifications --database
ABSOLUTE_SQLITE_FILE`，子命令为 `list-unknown`、`show`、`status`、`keep` 和
`retry`。沿用显式数据库目标、原 engine/Session 工厂、实际 Session 及文件系统
身份检查，不执行迁移、不直接发送 WS，不提供公网管理接口。

人工操作必须指定通知 ID、设备 ID、老人 ID、查询取得的修订号、操作 UUID、
操作者和受控原因码。`keep` 保留未知事实；`retry` 额外要求
`--authorize-duplicate`，并提示此前发送可能已成功、再次尝试可能重复通知。
只有仍为 `unknown`、修订号匹配、无有效认领、当前设备启用且老人/家属绑定
一致、告警未取消时，条件更新才可成功。状态与审计在同一事务提交，保留原
事件 ID、告警 ID 和累计尝试次数。相同操作 UUID 和参数重试返回原审计结果，
不增加授权；参数冲突拒绝。提交不确定返回失败，须查询审计后使用原 UUID核对。

工作者健康信息位于当前应用进程的 `app.state.delivery_worker.health()`，状态
为 `starting/running/stopping/stopped/failed`。任务完成回调主动发现意外退出，
只保存受控错误分类；心跳仅在实际循环完成后更新。显式 `restart()` 仅允许
旧任务已经结束，不重置数据库租约或未知状态。关闭超时仍保留原任务句柄。

公网 `GET /health` 健康时保留 `200 {"status":"healthy"}`；工作者非运行状态、
不存在或完成循环的心跳缺失/超过 10 秒时返回 `503 {"status":"degraded"}`。
不公开积压、数据库路径、设备、操作者或错误详情。CLI `status` 只查询数据库
积压，明确返回工作者状态不可跨进程获取，不将其伪装为运行或停止。
这些指标不证明送达、家属确认或全系统健康。详细操作见 [通知运维](通知运维.md)。

## 3. WebSocket 接口

### P1-02 家属消费者与 Header 兼容（2026-10-18）

握手凭证必须无歧义：Authorization 大小写不敏感，格式为 Bearer 加一个 ASCII
空格及非空凭证；不接受多余空白、逗号合并值或重复 Authorization Header。
重复 token 查询参数、空查询凭证也拒绝。Header 存在但格式或验证失败时不回退；
Header 与查询参数同时出现时必须逐字相同，否则关闭 4401。
之后继续使用原 JWT、启用状态、家属角色、周期复核及发送前老人归属校验。
旧查询路径仍有 URL/代理日志泄露风险；Header 也须避免被代理或诊断日志记录。
本次未改造部署代理，不能宣称已消除此风险。

实际消息仍为 `{type:"alert",data:{id,elder_id,alert_type,priority,content,status,created_at}}`。
稳定 ID 是 `data.id`，不是另造的 alert_id；created_at 为存储记录时间，不证明硬件事件发生时间。
客户端只接受当前绑定老人、已知类型和完整结构的消息，随后触发 REST 同步，
不直接拼装列表、不发送确认。列表沿用 GET /alerts 的裸数组及 ID 升序契约，
按当前老人筛选；同一 REST 结果中的重复 ID 仅展示一次。

应用级 AlertSocket 是唯一连接所有者。首页/告警页只持有可撤销订阅，隐藏或卸载
释放自己的订阅；应用后台主动关闭连接，回前台检查登录/绑定并恢复。
退出及账号切换清空订阅、缓存和旧会话数据，迟到的 SocketTask/REST 回调不得写入新会话。
老人切换只接受已从认证 REST 查询取得的绑定 ID，同时撤销旧订阅并重新同步。
平台未提供可靠的应用销毁回调；后台关闭和会话清理是本轮实现入口，不承诺后台保活。

连接状态含 idle、connecting、connected、reconnecting、exhausted、background、
auth_failed、platform_unverified、unsupported_url 和 cleanup_failed。
10 秒未打开连接视为失败；退避依次为 1/2/4/8/16 秒，最多连续重试 5 次。
连续稳定连接 30 秒或明确从后台恢复才重置额度，短暂开关不重置。
4401 停止重试并进入原登录流程；握手在 accept 前被拒绝可能只表现为传输错误，
故失败时以一次受控 REST 请求复核登录态，401/403 同样停止并清理。
REST 探测失败不冒充认证失败；不会无限轮询。前台恢复可再发起一轮有界尝试，
未增加网络恢复事件监听，因此不保证网络恢复后立即重连。

去重仅保存当前会话/老人最近 256 个稳定 ID，重连保留、切换清空，超限淘汰最旧 ID。
去重不是网络去重；已淘汰消息仍可能触发一次 REST 刷新，不会插入重复行。
突发通知合并为一个在途 REST 请求及至多一次待补同步；失败保持旧数据，不转为空列表。
每次连接打开均同步 REST，覆盖历史补推不保证完整的情况；unknown 不因此被服务端重发。
发送计数、客户端收到消息均不等于家属确认，现有通知状态机保持原样。

原生 SocketTask 没有本轮可依赖的 off 系列接口：关闭后通过连接代次使回调失效，
释放页面订阅及所有自有计时器。close 抛错/失败时停止普通重试并标记 cleanup_failed，
需排查或重启应用；无法强制终止不配合关闭的原生网络操作。
已在途 HTTP 不能由现有 Promise 工具直接取消，其迟到结果通过会话/页面代次隔离。
诊断只含状态、重试次数、缓存和订阅数，不含 URL、Header、JWT 或告警正文。

**微信兼容性边界**：2026-10-18 读取微信团队官方

## 4. 统一事件 JSON 格式

```json
{
  "eventId": "string",
  "type": "fall|sedentary|voice|config|alert",
  "priority": "P0|P1|P2",
  "timestamp": "ISO8601",
  "source": "edge|cloud|family",
  "payload": {},
  "authToken": "string"
}
```

- `type` 取值：`fall` 跌倒、`sedentary` 久坐、`voice` 语音、`config` 配置变更、`alert` 告警。
- `priority` 用于事件总线优先级调度：P0 > P1 > P2。
- `authToken` 用于内部事件鉴权，外部请求不使用该字段。

## 5. 插件统一接口

所有业务插件实现统一接口，内核通过事件总线分发事件，插件异常不影响内核与其他插件：

- `init()`：插件初始化
- `start()`：启动插件
- `stop()`：停止插件
- `handle_event(event)`：处理输入事件

## 6. AI 门面统一接口

AI 能力支撑层对外统一封装，屏蔽第三方差异；外部 API 失败时返回明确错误码，由上层执行兜底策略：

- `asr(audio)`：语音识别
- `tts(text)`：语音合成
- `intent(text)`：意图解析
- `behavior(image)`：行为识别（P1）
- `fuse(inputs)`：多模态融合（P2）

## 7. 契约校验

契约校验测试位于 `cloud-server/tests/test_contract.py`，用 Python 标准库对样例负载做结构校验（必填字段、类型、枚举、优先级），不依赖额外第三方库。新增/修改契约时必须同步更新该测试。
